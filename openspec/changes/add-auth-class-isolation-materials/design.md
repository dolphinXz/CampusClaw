# 设计

## 技术栈
- 后端采用 Java 21 + Spring Boot 3（Web、Security、Data JPA）。
- 数据库使用 MySQL 8，表结构由 Flyway 迁移脚本管理。
- 前端采用 Vue 3 + Vue Router + Vite。
- Web 前端与 API 一起由 Docker Compose 启动。

## 会话与密码哈希
- 登录态明确采用服务端会话（session + HttpOnly Cookie）。
- 提供账号密码登录接口，校验通过后创建会话；未登录访问受保护页面时跳转登录页。
- 密码使用 `argon2id` 或 `bcrypt` 哈希存储，禁止明文和可逆加密。
- `DATABASE_URL`、会话密钥和存储密钥只从服务端环境变量读取。

## 查询层班级隔离
- 用户、班级和材料都绑定明确的 `class_id`。
- 材料列表、详情和下载统一经过查询层，并强制追加当前用户的 `class_id` 条件。
- 不接受前端传入的 `class_id` 覆盖权限；跨班访问返回拒绝响应。

## 上传入库数据流
上传链路固定为：文件 → 解析 → 入库 → 列表。

1. 文件：教师上传材料文件和元数据。
2. 解析：服务端校验登录态、教师角色、班级归属，并解析材料内容。
3. 入库：保存材料内容或内容引用，并在 `materials` 表中写入 `class_id`、`uploaded_by` 和元数据。
4. 列表：刷新本班材料列表后能查询到该记录。

## 数据模型
- `classes`：班级基础信息。
- `users`：账号、角色、所属班级、密码哈希。
- `materials`：材料标题、所属班级、上传教师、内容引用、创建时间。

## 种子数据
- 提供至少一个班级。
- 提供一个教师账号和一个学生账号。
- 提供一条本班示例材料，用于验证列表可见性。

## Compose 与 healthcheck
- `docker-compose.yml` 启动应用、数据库和必要存储服务。
- 数据库和材料存储使用 Docker volume 持久化，重建容器后数据仍在。
- 提供免登录的 `GET /health`，返回服务可用状态。
- 健康检查不依赖业务登录态。
