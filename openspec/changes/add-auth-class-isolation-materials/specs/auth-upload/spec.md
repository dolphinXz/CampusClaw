# Spec Delta

## Purpose
为校园教学应用建立账号登录、角色权限、班级隔离、预置样本和教师材料入库的基础能力。

## ADDED Requirements

### Requirement: 登录与受保护访问
系统应支持教师和学生使用账号密码登录，并保护需要登录的页面和接口。

#### Scenario: 使用有效账号登录
- **WHEN** 教师或学生提交有效账号和密码
- **THEN** 系统应建立登录态并允许访问其权限内的页面

#### Scenario: 未登录访问受保护页面
- **WHEN** 未登录用户访问受保护页面
- **THEN** 系统应将其引导到登录页

### Requirement: 角色权限控制
系统应按用户角色限制材料上传能力。

#### Scenario: 教师上传材料
- **WHEN** 教师调用上传接口并提交有效材料
- **AND** 请求通过服务端角色校验
- **THEN** 系统应允许上传

#### Scenario: 学生上传材料
- **WHEN** 学生调用上传接口
- **THEN** 系统应返回 403

### Requirement: 班级数据边界
系统应把班级作为材料访问边界，并在服务端强制过滤。

#### Scenario: 同班访问材料
- **WHEN** 用户访问本班材料
- **THEN** 系统应返回该材料或本班材料列表

#### Scenario: 跨班访问材料
- **WHEN** A 班用户尝试访问 B 班材料
- **THEN** 系统应返回拒绝状态且不返回 B 班材料

### Requirement: 教师材料入库与本班可见
系统应把教师上传的材料写入知识库，并让同班用户在材料列表中看到记录。

#### Scenario: 教师上传材料后可查
- **WHEN** 教师成功上传材料
- **THEN** 系统应写入知识库
- **AND** 刷新后本班材料列表应包含这条记录

#### Scenario: 材料列表只显示本班记录
- **WHEN** 用户请求材料列表
- **THEN** 系统应只返回该用户班级下的材料

### Requirement: 六类核心数据与预置样本
系统应提供可用于验证登录、班级隔离和材料列表的六类核心预置数据。

#### Scenario: 初始化后存在六类核心数据
- **WHEN** 应用完成初始化或执行种子脚本
- **THEN** 系统应包含班级 A、班级 B、教师 A、学生 A1、学生 B1
- **AND** 班级 A 和班级 B 的材料都能在各自班级列表中查到

### Requirement: 密码哈希与密钥管理
系统应安全保存密码并限制密钥来源。

#### Scenario: 密码存储
- **WHEN** 系统保存用户密码
- **THEN** 系统应保存哈希值，不得保存明文密码

#### Scenario: 密钥管理
- **WHEN** 应用读取数据库、会话或存储密钥
- **THEN** 密钥应来自服务端环境变量

### Requirement: Compose 与健康检查
系统应能通过 Docker Compose 启动，并提供免登录的健康检查接口。

#### Scenario: 使用 Compose 启动
- **WHEN** 按 README 运行 Docker Compose 启动命令
- **THEN** 应用和依赖服务应能启动并连通
- **AND** 重建容器后已有数据仍然存在

#### Scenario: 健康检查
- **WHEN** 客户端请求 `GET /health`
- **THEN** 系统应返回成功状态表示服务可用
