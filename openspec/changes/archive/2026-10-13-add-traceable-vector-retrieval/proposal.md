# 提案：可追溯的知识库检索（关键字、向量与混合模式）

## Why
CampusClaw 已具备登录、班级隔离和材料入库，但材料入库后只能按列表整篇翻阅：无法按内容定位到具体段落，也无法基于本班材料回答问题。本变更在既有能力之上增加可追溯检索——把材料正文切成带字符范围的切片，同时建立 MySQL 中文全文索引和 Qdrant 向量索引；教师和学生可以用关键字、向量或混合模式检索本班材料，并从每条结果回到原材料。只有检索到可靠片段时才调用生成模型，没有依据时固定返回“资料中未找到相关内容”，不编造答案。

## What
- **范围修订**：撤销上一变更提案中“不做检索问答、不做全文检索/向量检索/智能问答”的非目标声明，README 三行范围说明同步修正；本变更通过新 capability `knowledge-retrieval` 修改项目范围，不改动历史变更文档。
- **正文与切分**：材料解析正文存入 `knowledge_entries.body_text`（原文件与 `body_text` 不得被预处理改写）；按 `auto`、`custom`、`hierarchy` 三种策略切成 `knowledge_chunks`，记录切片序号、字符范围、班级与材料关联、索引状态和失败原因。
- **中文全文索引**：MySQL 为 `chunk_text` 建 `FULLTEXT ... WITH PARSER ngram`，ngram token 长度为 2；查询只读 `index_status = ready` 且带会话 `class_id`。
- **向量索引**：Qdrant 集合 `campusclaw_chunks`（余弦距离）只保存固定维度向量和关联编号，不保存正文；point ID、`knowledge_chunks.id` 与 payload 的 `chunk_id` 保持一致，payload 至少含 `class_id`、`material_id`、`knowledge_entry_id`、`chunk_id`、`chunk_index`。
- **三种检索模式**：`keyword` 只查 MySQL；`vector` 问句嵌入 → Qdrant 按班级过滤 → 回 MySQL 取正文；`hybrid`（默认）两路各按绝对阈值过滤后用 RRF（`k = 60`）融合，全文分与余弦分不得直接相加。
- **可追溯结果**：每条命中返回材料标识和标题、切片序号、字符范围、来自 MySQL 的正文摘录、最终排序信息和打开原材料的入口；服务端存储路径与原始向量不返回前端。
- **班级隔离延续**：`class_id` 只从已认证会话获得，MySQL 查询、Qdrant 过滤、回表校验三处全部带班级条件；伪造的班级编号被忽略；跨班内容在检索中表现为 HTTP 200 无命中，按材料 ID 访问延续既有 404 规则。
- **有依据才生成**：`POST /api/ask` 先用混合检索取本班前 4 条切片；有切片才调用对话模型并以 `[1]`、`[2]` 对应 `citations` 顺序，无切片直接返回固定句且不调用模型；客户端提交的 `system` 消息丢弃，系统提示由服务端生成。
- **失败语义**：材料与正文保存成功后，即使嵌入或 Qdrant 写入失败，材料仍保留，对应切片标记 `failed`、不写入半截向量、不参与检索，教师可稍后重建索引恢复。
- **索引管理**：上传后自动建索引（未指定策略用 `auto`）；教师可显式重建单材料索引、补齐本班历史/种子材料索引；学生只读检索，上传与索引管理仍只有教师可执行。
- **交付面**：Compose 增加 Qdrant 服务与持久化卷；`.env.example` 只列配置项和安全占位值；前端在既有 AppShell 与设计令牌上新增检索页面（模式选择、结果出处、问答展示）；README 更新启动、配置、重建索引与验收说明。

## Capabilities
- `knowledge-retrieval`

## Non-goals
- 不重写登录、角色、材料上传和既有班级隔离，只在其上扩展。
- 不引入 Go 服务；后端保持 Spring Boot。
- 不做交叉编码器重排序、LangChain/LlamaIndex/Dify 编排或语义分句等额外能力。
- 不把 `chunk_text` 重复保存到 Qdrant，也不将 Qdrant、嵌入网关或对话网关暴露给浏览器。
- 不做流式输出、开放式长对话、模型自行检索或无依据自由回答；这些留待后续课程评审。
- 不做跨校或多租户组织体系、材料审批、版本管理或跨班分享（延续既有非目标）。
- 不在未更新本变更规约的情况下改变失败语义、阈值、默认切分参数或班级隔离规则。
