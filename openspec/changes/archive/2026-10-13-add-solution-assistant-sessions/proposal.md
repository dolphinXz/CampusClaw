# 提案：解题助手会话（提示词、解题引导技能与 SSE 流式问答）

## Why
第 4 课的 `/api/ask` 是单轮、非流式的有依据问答：没有可持久化的会话，无法连续追问；系统提示硬编码在服务端代码里，教师无法维护；「解题引导」这类教学行为无法配置。本课在既有登录、班级隔离、知识库检索之上构建可连续追问的解题助手：学生在会话中提问，服务端按「加载教师提示词 → 读取解题引导技能 → 检索本班知识库 → 生成回答」的固定链路执行，回答经 SSE 逐段返回，并把完整回答与引用持久化到会话中。提示词、技能、知识库三者必须共同参与同一次回答。

## What Changes
- **教师提示词**：新增 `system_prompts`（按班级一条），教师通过 `GET/PUT /api/prompt` 读取与保存；服务端在每轮回答时读取已保存提示词参与上下文组装，保存后从下一轮对话生效；学生无权修改（403），提示词内容只存服务端。
- **解题引导技能**：新增 `ai_skills`（按班级 + 技能代码唯一），系统预置至少一条「解题引导」（`solution-guide`）技能；教师通过 `GET /api/skills`、`PUT /api/skills/{id}` 维护内容与启用状态；启用时把技能指令注入上下文（引导分析问题、拆解步骤、指出本班材料出处、不直接给最终答案），关闭时同一问题的回答方式明显不同；学生无权开关（403）；技能状态与内容由服务端管理。
- **会话与消息**：新增 `chat_sessions`（归属某用户与班级）与 `chat_messages`（user/assistant 消息、引用 JSON、检索依据标记）；学生可新建会话、在会话中连续追问，消息全部持久化；会话访问只认归属用户，他人或他班会话与「没有这条数据」一致（404）。
- **SSE 流式问答**：新增 `POST /api/sessions/{id}/messages`，响应 `text/event-stream`；服务端先保存学生消息、加载提示词与技能、用本班 hybrid 检索前 4 条切片构造上下文，再调用支持 `stream` 的对话网关逐段转发（`delta` 事件），结束发送 `done` 事件（含引用与消息 ID），完成后把完整回答与引用持久化；检索未命中时如实返回「资料中未找到相关内容」且不调用生成模型、不编造引用；网关或嵌入故障在流开始前返回 503。
- **ChatClient 流式调用**：对话网关客户端新增 OpenAI 兼容 `stream: true` 的增量回调接口，服务端逐段转发给客户端；密钥与上游响应仍不泄漏。
- **OpenAPI / Swagger**：引入 springdoc，提供 `GET /v3/api-docs` 与浏览器可访问的 Swagger UI（含 Bearer 认证配置与 SSE 响应类型说明），文档路径、参数、响应与实际接口一致。
- **接口自动化测试**：新增仓库根目录 `apitest/`，按 URL 路径组织「一接口一脚本」，`run_all.py` 一键执行并生成 HTML 报告（报告目录加入 `.gitignore`）；测试核对状态码、响应结构、数据库一致性、权限拒绝、跨班 404、SSE 逐段接收与完整性。
- **前端**：学生新增解题助手页（会话列表、新建会话、SSE 流式聊天、引用展示）；教师新增提示词与技能设置页；沿用既有设计令牌与 AppShell。
- **范围修订**：README 与主规格「不做流式输出」的旧边界由本变更取代；不修改历史归档 change。

## Capabilities
- `assistant-sessions`

## Non-goals
- 不做作业提交、作业批改、错题讲解技能、关怀式对话技能与异步任务队列（课件明确排除）。
- 不引入 MCP 协议、子代理编排、多技能渐进式披露或跨应用工具共享；本课只有服务端固定执行的单技能链路。
- 不重写登录、角色校验、材料上传、既有班级隔离与第 4 课检索/`/api/ask` 的行为，只在其上扩展。
- 不改变既有检索阈值、失败语义、切分参数与班级隔离规则；检索能力不另做独立页面，只接入助手流程。
- 不做开放式无边界长对话：会话历史只用于理解追问（保留最近有限条），检索只使用最新问题。
- 不将对话网关、Qdrant 或密钥暴露给浏览器；SSE 只承载模型增量文本与引用元数据。
